# 今日补学与学习火花

用户已批准：学生首页展示 1–3 项个性化补学，小芯展示有效学习火花；推荐有原因、反馈和复测入口。首版采用本地知识点匹配与规则排序，不新增外部学生数据传输。

实施顺序：
1. 增量迁移保存提问的公开知识点上下文、账号私有补学会话和推荐反馈；历史问题只做本地保守匹配。
2. 结合最近提问、未解决错题和实验记录筛选候选；提问/实验关联仅作为线索，诊断与复测由服务器判分。优先考虑有证据的前置难点，跨章节适度去重。
3. 首页推荐卡支持诊断 → 知识讲解 → 练习 → 不同题号复测，保存进度、重试和账号恢复；题量不足明确标记，不能授予复测通过。
4. 学习火花按北京时间的有效学习日聚合；单纯聊天、浏览和自报完成不计分，同日重复活动封顶，火花不影响成绩或原知识图谱掌握状态。
5. 服务/路由测试验证冷启动、拒绝课程范围问题、推荐原因、反馈冷却、旧证据消退、复测题号隔离、服务端判分、重放和账号隔离；单浏览器/页面使用内存账号验证首页、断点恢复、小芯和窄屏。构建并检查首屏预算。

风险与边界：知识目录比题库更细，有些知识点仅有一道或没有题。此类提供公开讲解与资料导航，清楚标记证据不足；只有不同题号的练习和复测都通过才标记本轮复测通过，不宣称长期掌握。GKK 无播放进度接口，不能把打开讲演当学会。

完成标准：真实记录驱动推荐；学生可纠正推荐；无记录有诊断起点；推荐进度与火花跨刷新恢复；教师仅使用自身试练数据；演示账号遵守全局只读；不污染课程评分、不发送历史到模型。

## 已实现

- `ai_conversations.concept_ids_json` 记录公开知识点关联；旧历史读取时本地匹配，不修改原文。短词与共享的泛化标签不强行定位概念；未定位的近期章节提问可提供本章自测起点。
- `study_remediation_sessions` 保存诊断、讲解、练习、不同题号复测及判分证据；`study_recommendation_feedback` 保存稍后再学（一天）或非难点反馈（七天）。新答题错误可重新打开推荐。
- 所有 `/api/{student|teacher}/study-recommendations` 接口只读取当前账号。服务器判分并忽略客户端分数/verified，重复请求返回原结果。复测不能用练习/诊断题，也不能靠看过答案后的重复答对领取突破。
- 首页最多三项，考虑有证据的前置知识并适度分散章节。两道不同题的后续答对记录或本轮复测通过会降低旧难点推荐，七天后可进入间隔自测。题量不足时只记录阅读/练习，明确缺少复测证据。
- 小芯与首页同步显示火花：有效答题或实验通过每天 +2；完成有正确练习证据的补学每天 +3；首次知识点复测通过每天最多 +5，合计每日最多10。按 Asia/Shanghai 日期聚合，累计火花与连续有效学习日分开记录，不覆盖成绩或图谱掌握状态。
