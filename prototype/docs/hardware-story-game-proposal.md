# 装机剧情玩法调研草案

日期：2026-10-03。状态：玩法建议，尚未实施界面改版。

## 推荐方向

以“新入职的装机工程师”为玩家身份，通过客户对话获取需求，在 3D 工作台完成装配和排查，验机后交付，获得客户评价并解锁后续工单。先用第一张办公电脑订单验证完整体验，再扩展到其他订单与教材章节。

对话负责需求、线索和人物关系；直接操作负责安装、接线、检测；结算负责反馈选择的结果。每一轮都需要一次会影响方案的选择，以及一个可见的完成结果。

## 第一单示例：明天要用的办公电脑

1. 客户出现：“我明天要做汇报，这台电脑开很多表格就卡，预算最多 2200 元。”
2. 玩家可追问“主要运行什么软件？”、“需要保存多少资料？”或“现在是什么配置？”。回答形成需求便签；便签明确显示预算和用途。
3. 玩家选择配置并在 3D 工作台安装处理器、两根内存、存储与必要连接。零件装入有卡扣音、短暂目标反馈和步骤完成提示。
4. 验机：主机立放到桌旁，显示器经过数秒显示启动结果。配置不满足客户目标时，给出可定位的原因并允许返回修改。
5. 交付：客户反馈与实际配置一致，显示成本、报价、教学评价和工单完成情况，解锁下一张工单。

同样的对话选择必须能产生真实影响，例如揭示容量需求、改变预算约束或决定推荐方案。客户称赞和奖励只能由实际装配、启动和提交结果触发。

## 界面与节奏

- 工作台成为操作阶段的主要画面；订单列表、详细参数和经营数据收进可打开的面板。
- 对话使用角色名、头像和两到三个回复选项；需要完整阅读时支持点击继续，长对话可以跳过。
- 当前目标和完成动作出现在工作台旁，玩家能同时看到操作与结果。
- 每单包含接待、准备、操作、验机、交付五个阶段。阶段切换使用短镜头或提示，让玩家知道事情向前推进了。
- 安装音、卡扣音、电源音和客户反馈组成主要声音反馈；设置中提供静音和减少动画。
- 教师仍能查看课程进度、操作证据和评分。虚拟经营奖励与课程评分分别展示，参与型实验沿用原有“不计分”口径。

## 首个可评审版本

先完成一个约三到五分钟的完整工单：一个客户、一段可选择对话、一张需求便签、现有 3D 装机流程、一段验机表现和一次客户交付反馈。检查对话是否能影响配置、失败是否能被理解并修正、结束后是否知道下一步。

后续再增加老客户回访、故障订单、工程师等级和其他章节的角色委托。暂不以大量对白或多种成长货币作为第一版的完成标准。

## 对话实现方式

首单可以使用明确的剧情节点和条件选项。若后续出现大量分支，可以评估 [ink](https://www.inklestudios.com/ink/)：官方提供分支叙事脚本、测试编辑器以及 JSON 导出。无论采用哪种方式，装配与判分依旧由本系统的实际状态决定。
