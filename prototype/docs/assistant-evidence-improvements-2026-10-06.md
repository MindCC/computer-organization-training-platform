# 参赛建议落实与验证（2026-10-06）

## 本轮修改

1. 下次课堂的每条安排显示具体依据、来源类型和记录数量。有学情依据时，AI必须逐条引用有效ID；缺失或非法引用触发本地规则回退。引用合法性校验不代替解释正确性审核。
2. 原始报告由服务端保存为教师所属快照；采纳时仅提交报告ID，服务器查询来源。学生和其他教师不能读取该报告。
3. 任务草稿保存教师调整说明、教学安排和节点信息；编辑页面显示最近20次保存记录及相对原建议的变化，发布课堂对应具体任务版本。
4. 班级仅有概览、尚无诊断记录时，明确提示收集学习证据；不据此断言具体概念错误。旧任务没有来源时不补造记录。
5. 修订参赛方案中的过期实现描述和未经验证的效果表述，提供[真实试教与独立评测采集包](competition-validation-kit/README.md)。五份CSV均只有字段头。

## 教师操作路径

班级学情 → 生成助教建议 → 查看各条课堂安排的依据 → 采纳为课堂草稿 → 调整重点、步骤、讲解和任务节点 → 填写可选调整说明 → 保存任务 → 发布到课堂。

重新打开任务编辑页，在“建议来源与教师调整记录”查看原报告、保存版本与发布记录。已有报告需重新生成后才能获得服务器保存的来源ID。

## 验证结果

- 全量单元测试：658项通过；补充权限断言后的接口测试17项通过。
- 生产构建与首屏门禁：508,198 / 512,000字节。
- 生产浏览器：真实服务端判分产生全加器错误记录 → 逐条证据 → 采纳 → 两次教师修改 → 重载 → 发布版本关联 → 学生响应隐私检查；390像素宽度无横向溢出。
- 课堂负载：150名学生、并发30，150/150成功，SQLITE_BUSY为0；本次本机P95为37毫秒。该结果不等同于部署服务器容量。

测试使用隔离数据库与生产构建快照，未使用正式学生数据或外部模型调用。旧通用教师浏览器回归仍有界面定位器问题，本轮专项链路验收通过不代表所有浏览器脚本均通过。

## 仍需真实证据

优先开展一个班级的两次教学活动，采集不同题号的复测、教师工时与学生反馈；再整理30～50个独立教师审核案例比较普通问答、工具助教和本地规则。当前工程验收与合成评测不能证明真实课堂学习提升，也不能代替跨课程推广验证。
