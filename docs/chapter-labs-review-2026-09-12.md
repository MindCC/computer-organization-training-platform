## 2. 不妥之处（模型层，可复现）

### 2.1 `machine-number`（机器数编码）：实验根本不成立

- 节点 `sign-split` / `magnitude-split` / `ones-encoder` / `twos-encoder` 的类型全是 `"buffer"`；`circuitSimulation.js:31` 的 buffer 只是把输入原样透传，**不会做取反、也不会 +1**，"补码生成器"名不副实。
- 输入 `decimal-input` 只有一个 `bit` 信号（标签写成 `-5`），测试用例是：
  - `{名:"-5 编码路径", inputs:{decimal-input.out:1}, expected:{"machine-output.in":1,"sign-output.in":1}}`
  - 即所有断言都只检查"线路连通后，1 沿路径传到终点"，**没有任何一次性数值验证**。
- 结论：这是"照着参考图连线"的参与型活动，不是编码实验；标签（原码/反码/补码/±5）会让师生误以为验证过编码正确性。

### 2.2 `multi-adder`（多位加法器）：用黑盒冒充"多个全加器串联"

- 三个位级节点类型是 `"fullAdder"`（`circuitSimulation.js:63` 内置全加器），学生只需要把 Cin 链从低位接到高位。
- 章节目标写的是"能够构建串行、并行的算术逻辑单元"，但这里没有让学生用**已解锁的芯片/门**拼出一个全加器，缺乏"由门到功能部件"的关键一跃。

### 2.3 `full-adder`（全加器）与 `alu`（简化 ALU）：进位逻辑是黑盒

- `full-adder` 的 `carry-logic` 直接用 `fullAdder` 组件产 Cout，`requiredEdges` 要求 9 条线（含三条进 carry-logic），比"两个半加器 + 一个或门"多两条，**教的是接线而不是结构**。
- `alu` 的 `alu-core` 是 `alu1` 黑盒（`circuitSimulation.js:86`），学生连上 a/b/cin/op 就直接得分，等于没有实现运算选择。

### 2.4 芯片库 `chip:half-adder` 等实际不可用，且"非门芯片"算错

- `CHIP_DEFINITIONS` 定义了半加器/全加器/四种门的可复用芯片，`getUnlockedChips`/`buildChipPalette` 也有实现，但**前端没有任何地方调用**（`src/components` 里搜不到 chip 相关引用），所以"完成关卡解锁芯片"这条设计线是断的。
- `not-gate` 芯片的 `simulation: ({ inp }) => ...` 参数名与端口 id（`in`）不一致。实测：
  ```
  A=0 -> {"out":1}
  A=1 -> {"out":1}
  ```
  恒为 1。单元测试只断言 id/端口结构，未跑仿真，所以没暴露。

### 2.5 数据流/信号语义过弱，容易被当成"真电路"

- buffer 节点（五大部件、程序运行路线、存储器访问、机器数编码大量使用）在 UI 上等同于"导线"，但页面呈现的是"存储器""控制器""补码生成器"这类功能部件。
- 学生通过的其实是"端点连线题"，过程性诊断（`realtimeDiagnostics`）也只能说"某条线没连"，无法解释"为什么结果错"。

## 3. 不妥之处（内容与映射层）

### 3.1 章节↔实验映射挂错/自相矛盾

- `data-flow`（认识数据流）被挂在**第一章**，但它的前置 `LEARNING_ITEMS` 顺序在"基础逻辑门"组里，内容也属于第三章的"逻辑运算"。
- 第一章的五大部件图缺"寄存器"（教材版是 5 大部件：运算器、控制器、存储器、输入、输出；部分教材把寄存器单列）——目前 3D 与连线实验的部件命名不统一，需要在课程口径上定稿。

### 3.2 第五章"指令系统"没有真正的实验

`instruction-data`（PC→地址100→IR→操作数→结果寄存器）与 `program-flow`（键盘→主存→CPU→屏幕）只验证"顺序连线"。第 5 章的核心（指令格式、寻址方式、RISC）**没有任何可操作、可判分的实验**。

### 3.3 第四章只覆盖了很小一块

`memory-address` 只考 MAR→主存→MDR→数据总线。第四章 178 页讲义的重点——**Cache 三种地址映像、命中/缺失、虚拟存储页表转换**——都没有实验，也没有对应的判分模型。

### 3.4 六年级目标悬空（第 6/7/8 章）

三章在大纲里各写了 2～3 条"掌握/熟悉"级目标，但平台上没有任何实验、判分或学情数据落点；教师看板的章节覆盖率会在这三章显示为空。

## 4. 修改方案

### 阶段 0：先修"错"的（1～2 天，纯模型/数据改动，不动 UI 框架）

| 优先级 | 动作 | 改动文件 | 验收 |
|---|---|---|---|
| P0-1 | 修 `not-gate` 芯片仿真参数名，并给它和其余芯片补仿真单测 | `circuit/chipDefinitions.js`、`chipDefinitions.test.mjs` | `A=0→1`、`A=1→0`；六种芯片真值表全对 |
| P0-2 | 补 `memory-address`、`machine-number` 的 `REFERENCE_SLOT_LAYOUTS` | `labPlacement.js` | 蓝图不再走 fallback，槽位 role 与实验部件一一对应 |
| P0-3 | 章节↔实验单一来源：给 `CHALLENGES` 每项加 `chapterId`，`courseware.js` 的 `linkedChallenges` 由它派生（而不是手写两份） | `platformLogic.js`、`courseware.js`、新增一致性单测 | `data-flow→ch3`、`mux` 不再孤儿、8 章每章列表可自动生成 |
| P0-4 | 建"章节—实验—判分类型"清单：把每个实验标为**参与型**（只记完成）或**评分型**（服务端可复算），页面与教师看板分别展示 | `platformLogic.js` + 展示层 | 参与型不再冒充测评分数（与 `docs/project-review-2026-09-04.md` 第 09 条一致） |

### 阶段 1：把已有的 3 个实验做实（约 1 周）

1. **`machine-number` 重做**：输入改为 2 位可切换位（或一个有符号 4 位数），节点用 `not`（取反）+ 加法路径（+1），测试用例断言**具体补码位型**（如 -5 → `1011`）；`expected` 覆盖"原码/反码/补码"三组输出。若现有仿真器无法表达 +1，则显式降级为"参与型"并在页面标注"本活动只演示编码流程，不做数值判定"。
2. **`full-adder` 改为可拼装**：节点换成两个 `chip:half-adder` + `or`（芯片库已具备），`requiredEdges` 收敛为真实结构，测试用例保留 4 组真值表。
3. **`alu` 改为可拼装**：`alu-core` 拆成 `fullAdder`/`and`/`or`/`xor` + `mux2` 结果选择器（或放开 `mux` 前置），标志位由门电路产生。
4. **打通芯片解锁链路**：把 `getUnlockedChips`/`buildChipPalette` 接进元件面板，让学生用已完成的半加器拼全加器——这一步同时补上"由门到部件"的教学断层。

### 阶段 2：补第六、七、八章实验（每章一个，约 1～2 周）

优先做"顺序/判别/对比"型，避免依赖新的物理仿真：

| 章节 | 实验 | 交互 | 判分（服务端可复算） |
|---|---|---|---|
| 6 CPU | **单指令数据通路单步** | 给出简化数据通路（PC/IR/寄存器组/ALU/存储器），学生按取指→译码→执行→访存→写回排步骤并选择每拍控制信号 | 每拍的控制信号组合 + 阶段顺序；错误定位到"第几拍、哪个寄存器值不对" |
| 7 总线 | **总线判优与通信方式对比** | 把链式查询/计数器定时/独立请求三种判优按给定设备请求顺序排出谁先获得总线；再对同步/异步握手排时序 | 判优顺序序列、握手应答顺序 |
| 8 I/O | **中断与 DMA 流程排序** | 把中断处理的 6 步（关中断→保存断点→识别中断源→服务→恢复→开中断）与 DMA 三阶段（预处理→传送→后处理）排成正确序列，并判断给定场景该用查询/中断/DMA | 序列 + 场景选择题 |

三章共用一个"排序/选择"判分器即可，不需要新建模拟内核；数据模型沿用 `CHALLENGES` 的 `requiredConnections` 语义，但判分改为"有序步骤 + 选择题答案"的服务端复算。

### 阶段 3：补齐第四、五章的薄弱点（可选，按课时取舍）

- 第 4 章：加 **Cache 地址映像对照**（直接/全相联/组相联给定地址算出组号与命中情况）与 **页表转换**（虚拟地址→物理地址）两个小实验，都是纯计算型，服务端易判。
- 第 5 章：加 **指令格式分析**（给定位宽拆操作码/地址码并判断可表示指令数）与 **寻址方式计算**（基址/变址/相对寻址求有效地址）。

### 阶段 4：在课程口径上定稿

- 明确并统一"五大部件"是否含寄存器、各章实验是必做还是选做；把这些写进 `courseware.js` 的章节元数据，避免页面、3D、教师看板三处各说一套。

## 5. 验收标准（每个阶段都要跑）

1. `npm test` 全绿；新增/调整的模型必须有单测覆盖（真值表、期望位型、判分顺序）。
2. `challengeCircuitModel.test.mjs` 的"关卡 ↔ 结构化模型 一一对应"约束保持不变。
3. 新增章节映射后：**八章中每章至少 1 个实验**，且 `mux` 等不再出现"已注册但无章节归属"。
4. 参与型实验在教师看板与学生结算里不得显示为分数（与服务端"不采信客户端分数"的既有约束一致）。
5. 浏览器门禁：`npm run qa:3d`（若改到 3D 概览）、`npm run qa:classroom`（若改到课堂提交链路）按改动范围执行。
