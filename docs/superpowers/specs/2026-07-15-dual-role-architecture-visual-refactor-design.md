# 双端架构与视觉重构设计

**日期：** 2026-07-15  
**状态：** 已完成对话评审，等待书面规格确认  
**适用范围：** `prototype/` React、Express 与 SQLite 课堂平台

## 背景

项目已经具备学生课程路线、实验工作台、React Flow 电路、Three.js 计算机拆解、硬件配置挑战、教师班级管理和 AI 助教等完整能力，但功能增长已经超过当前架构承载能力。

审计确认了以下基线问题：

- `prototype/src/App.jsx` 约 1135 行，同时持有认证、学生、教师、实验、笔记和硬件挑战状态。
- `prototype/src/styles.css` 约 5900 行，包含多个局部变量体系和重复响应式断点。
- 生产入口 JavaScript 约 1369 KB，gzip 后约 385 KB；Three.js 与硬件挑战仍通过静态依赖进入主包。
- 三张主要 PNG 资源合计超过 4 MB。
- 现有 125 项测试通过 124 项；失败测试依赖本机是否存在 `DEEPSEEK_API_KEY`，可能误走真实 AI 请求。
- 教师首页会把 `{ type, count }` 高频瓶颈对象直接作为 React 子节点渲染，登录后稳定崩溃。
- 学生首页存在 `game-*` 内部标识、`- 分钟` 和与实际推荐关卡矛盾的欢迎文案。
- 学生路线名义上是“路线地图”，实际表现为超长的同质卡片墙。
- 当前 Playwright 截图中的 3D 场景主体接近全黑，且控制台出现 Three.js 弃用警告。

审计截图保存在 `prototype/test-artifacts/architecture-audit-2026-07-15/`。这些截图仅作为当前设计证据，不纳入设计文档提交。

## 目标

1. 学生端与教师端同等优先，共享一套统一的科技实验室设计语言。
2. 把大型应用组件拆分为清晰、可独立理解和测试的功能边界。
3. 在普通教室 Windows 电脑上保持稳定、流畅、可降级的体验。
4. 保持现有 SQLite 数据、HTTP API 和课堂部署方式向后兼容。
5. 通过边界校验、错误隔离和自动化测试降低回归概率。
6. 保留并安全吸收当前未提交的 3D、路由和验证脚本改动。

## 非目标

- 不重写整个产品，不更换 React、Express 或 SQLite。
- 不引入新的全局状态管理框架，除非后续实施证明局部状态无法满足需求。
- 不改变现有用户、班级、进度、笔记和提交记录的业务含义。
- 不以高端独立显卡为默认运行条件。
- 不在本轮增加与架构、双端核心体验或稳定性无关的新业务功能。

## 总体策略

采用渐进式双端重构，而非视觉覆盖或整体重写：

1. 先修复阻断性错误并建立可信测试基线。
2. 建立共享应用外壳、设计系统、API 适配器和功能边界。
3. 重构学生路线、实验工作台和轻量 3D 体验。
4. 重构教师仪表盘、班级操作和 AI 助教。
5. 最后完成性能、可访问性和视觉一致性收尾。

每个阶段都必须保持应用可运行、可测试和可回滚。

## 前端架构

### 应用层

`App.jsx` 只负责：

- 启动应用和恢复会话；
- 选择学生或教师入口；
- 渲染共享外壳；
- 承载全局通知和顶层错误边界。

实验状态、笔记状态、班级状态和 AI 状态不再驻留于应用根组件。

### 功能边界

- `features/auth`：登录、退出、会话恢复和角色守卫。
- `features/student/home`：课程路线、推荐任务和进度摘要。
- `features/student/lab`：实验工作台、React Flow、传统连线实验和 3D 探索。
- `features/student/hardware`：硬件配置挑战。
- `features/student/records`：学习记录与个人报告。
- `features/student/notes`：笔记查询、编辑和关联关卡。
- `features/teacher/dashboard`：班级健康度、风险学生和待办事项。
- `features/teacher/classes`：班级、学生导入和账号操作。
- `features/teacher/students`：学生详情和进度趋势。
- `features/teacher/assistant`：AI 助教和本地降级分析。
- `domain`：电路模型、判题、仿真、课程进度和硬件配置等纯逻辑。
- `shared/ui`：设计令牌、布局、按钮、卡片、状态、表格和反馈组件。
- `shared/api`：请求客户端、响应校验、兼容适配和错误分类。

每个功能自行管理状态和副作用。共享层不得反向依赖学生或教师功能。

### 加载策略

学生端、教师端、React Flow、Three.js 和教师分析按角色和页面懒加载。登录页与共享外壳不加载实验引擎。Three.js 必须是独立功能块，离开页面后释放渲染资源、事件监听和计时器。

## 后端架构

在保持现有 URL 和响应兼容的前提下，把 `server/app.js` 与 `server/db.js` 渐进拆分为：

1. **路由层**：解析 HTTP 输入、认证角色、映射状态码。
2. **服务层**：执行班级、学生、提交、笔记和 AI 业务规则。
3. **数据访问层**：封装 SQLite 查询、事务和数据转换。

现有 API 不改名。新内部接口通过适配器继续返回旧客户端需要的字段，直到全部调用方迁移完成。

## 数据流与契约

统一数据路径为：

`SQLite → 数据访问层 → 业务服务 → API 响应 → 前端适配器 → 页面视图模型`

页面组件不得直接渲染后端原始对象。适配器负责默认值、枚举转换、字段缺失和旧数据兼容。例如，教师端高频瓶颈统一转换为 `{ label, count }` 视图模型，组件只渲染 `label` 和 `count`。

关键请求和响应使用运行时校验及 JSDoc 类型约束。异常数据进入可恢复错误状态，而不是触发整页崩溃。

## 统一视觉系统

设计语言为“科技实验室”：

- 米白和浅灰构成基础空间；
- 深海军蓝用于主要操作和核心标题；
- 青绿色用于进度、成功和信号流；
- 橙色用于提醒和待处理项；
- 电路走线、端口和信号流作为品牌图形语言；
- 减少大面积玻璃模糊、重阴影和纯装饰动画；
- 统一字号、间距、圆角、边框、状态色和焦点样式。

学生端和教师端共享组件与令牌。学生端强调沉浸和行动指引，教师端提高信息密度，但不形成两套互不兼容的主题。

## 学生端设计

### 首页

- 把超长卡片墙改为电路板式学习路线。
- 首屏只显示当前任务、总体进度、最近成果和一个明确的继续按钮。
- 默认展开当前章节和相邻节点，其余章节折叠为里程碑。
- 明确区分当前、已完成、可开始和锁定状态。
- 所有标题来自正式课程元数据，不展示内部 ID。
- 缺失的时间预测显示“待评估”，不显示负值或占位符。
- 欢迎文案与实际推荐关卡来自同一视图模型。

### 实验工作台

统一为“任务步骤—中央工作台—实时反馈”结构。React Flow、传统实验和 3D 探索共享导航、任务信息、提交反馈和返回路径，具体工作区可以独立实现。

### 3D 探索

- 提高材质、轮廓、标签和背景的对比度。
- 默认使用有限光源、有限阴影和按需动画。
- 提供自动爆炸、分步组装和部件查看的清晰选中状态。
- 低性能、WebGL 不可用或上下文丢失时切换到可交互的分层静态视图。
- 降级视图保留部件说明、装配顺序和总线关系，不允许只显示空白或黑屏。

## 教师端设计

- 首屏优先显示班级健康度、风险学生、共同薄弱点和待处理事项。
- 班级切换、学生导入和查看详情保持稳定位置。
- 学生表格、趋势和摘要使用较高信息密度，但延续统一组件和状态语言。
- AI 助教作为辅助决策区，不抢占班级核心数据。
- AI 失败时显示本地分析、失败类别和可执行的下一步，而不是模糊错误。
- 空班级、无提交、部分数据失败和全部失败都有独立状态。

## 错误处理

### API 层

区分认证失败、输入错误、资源不存在、冲突、AI 不可用和服务器异常。无效 JSON 返回 400，不能统一映射为 500。

### 功能层

学生实验、教师仪表盘、3D 场景和 AI 助教分别设置错误边界。单个功能失败不应让整个应用白屏。

### UI 层

每个异步界面包含加载、空数据、部分失败、重试和降级状态。用户提示使用中文行动建议，不显示内部堆栈。

### AI 层

AI 配置、网络请求和超时通过依赖注入提供。测试环境明确禁用真实网络。生产失败时使用本地规则生成可用报告。

### SQLite

保留 WAL 模式，增加明确的忙等待配置，并确保批量导入、提交和进度更新位于清晰事务边界内。

## 性能预算

- 学生或教师首屏 JavaScript 目标不超过约 250 KB gzip。
- React Flow、Three.js 和教师分析不得进入通用首屏包。
- 常规图片单张原则上不超过 300 KB，并提供适合显示尺寸的 WebP 或 AVIF。
- 普通教室 Windows 电脑上的 3D 基线为稳定 30 FPS。
- 低性能或 `prefers-reduced-motion` 环境关闭粒子、软阴影和连续动画。
- 页面切换后 WebGL、事件监听、计时器和异步任务不得持续增长。
- 生产构建不得出现通用入口超过 500 KB 的警告；大型 3D 块必须保持按需加载。

## 可访问性

- 保留并统一 `focus-visible` 样式。
- 所有图标按钮必须有可访问名称。
- 关卡状态不能只依赖颜色表达。
- 关键文本和控件满足可读对比度；最终数值需要在实现阶段使用实际颜色测量。
- 键盘可以完成登录、导航、班级切换和核心实验操作；纯空间型 3D 操作提供等价的列表或分步控制。
- 响应式布局以 1366×768 为主要桌面基准，窄屏重新排列信息架构，不简单压缩三栏。

## 测试策略

### 单元测试

覆盖判题、进度、数据适配、默认值、无效数据和课程元数据。为 `{ type, count }` 高频瓶颈增加明确回归测试。

### API 集成测试

使用内存数据库和注入式 AI 客户端。测试必须清理或显式设置环境变量，并禁止访问真实网络。

### React 渲染测试

覆盖学生与教师入口、空数据、异常数据、角色差异、错误边界和降级视图。

### Playwright

使用单个无头 Chromium 和单 worker，覆盖：

- 教师登录和仪表盘；
- 班级创建、学生导入和学生详情；
- 学生登录、课程路线和实验提交；
- 3D 正常路径和降级路径；
- 刷新后的会话与数据恢复；
- 关键页面无未处理异常和非预期控制台错误。

内置浏览器不作为默认测试工具，以避免已知的内存压力。

## 分阶段交付

### 阶段 1：稳定性基线

修复教师端对象渲染崩溃、AI 环境污染、无效课程标题与时间显示，并建立可信回归测试。

### 阶段 2：共享架构

建立应用外壳、功能目录、API 适配器、设计令牌、通用组件和路由级懒加载。

### 阶段 3：学生端

重构课程路线、实验工作台和轻量 3D 体验，增加静态降级方案。

### 阶段 4：教师端

重构班级健康度、风险队列、学生详情和 AI 助教。

### 阶段 5：质量收尾

执行性能预算、可访问性检查、Playwright 全流程和生产构建验证。

## 兼容与变更保护

- 不重置或覆盖当前工作树中的 3D、路由和验证脚本改动。
- 实施前先为现有行为补充测试，再进行结构移动。
- 每个阶段采用小提交，提交内容只包含该阶段相关文件。
- SQLite 数据和现有 API 保持兼容；必要转换放在适配层。
- 审计截图和临时审计数据不进入产品提交。

## 验收标准

1. 教师和学生登录后都能进入可用首页，不出现未处理 React 异常。
2. 学生首页不显示内部 ID、负时间或与推荐任务矛盾的文案。
3. 教师首页能正确显示高频瓶颈对象和空数据状态。
4. 3D 不可用时自动展示包含完整教学信息的降级视图。
5. 所有测试通过，测试运行不访问真实 AI 服务。
6. 生产构建成功，首屏和大型功能块符合性能预算。
7. Playwright 双端核心流程通过，关键页面无未处理异常。
8. 现有数据库可以直接启动，原有 API 调用保持有效。
