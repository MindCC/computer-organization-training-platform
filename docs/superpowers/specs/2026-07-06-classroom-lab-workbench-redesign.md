# 课堂实验工作台视觉与功能升级设计

日期：2026-07-06

## 背景

当前平台已经具备课堂集中版的关键能力：账号登录、教师/学生角色、班级管理、CSV 导入、学生进度保存、React Flow 电路实验、教师看板、AI 助教、硬件配置挑战。下一步的问题不是继续堆功能，而是把这些能力组织成一个更像正式教学产品的“课堂实验工作台”。

本设计参考以下开源项目的产品思路：

- CircuitVerse：在线数字逻辑电路平台，适合参考“电路画布 + 元件库 + 交互式教材”的组合。
- Microsoft MakeCode / PXT：面向初学者的学习型 IDE，适合参考“左侧教程/导航，中间操作区，右侧模拟器/反馈”的布局。
- CREATOR：计算机体系结构教学模拟器，适合参考“架构状态、步骤执行、理论到实践”的教学闭环。
- Open edX：适合参考教师端信息架构，但不照搬完整 LMS。

## 目标

- 把学生端从“课程页面 + 实验页面”升级为清晰的课堂实验工作台。
- 把教师端从“能看数据”升级为“课前、课中、课后都能快速决策”的教学驾驶舱。
- 在视觉上减少大块渐变和营销式卡片，改为更清爽、密集、可扫读的教育 SaaS / 学习型 IDE 风格。
- 在功能上优先增强实时检测、数据流观察、教师学情解释和课堂首用流程。
- 保持当前后端、React Flow、判题、SQLite、AI 助教边界不变，降低交付风险。

## 非目标

- 不做完整 CircuitVerse 克隆。
- 不做完整 MakeCode 克隆。
- 不做完整 Open edX / LMS。
- 不做公开注册、多租户、课程市场、在线支付。
- 不做任意自由电路沙盒，仍然以课程关卡为主。
- 不做完整 CPU 微架构仿真，先做能服务课堂讲解的步骤模拟和数据流观察。

## 产品定位

平台应定位为：

> 面向《计算机组成原理》课堂的学生实验工作台与教师助教看板。

学生看到的是“我现在学到哪、该做哪个实验、当前结构哪里错、数据怎么流动”。教师看到的是“这个班哪里卡住、下一节讲什么、哪些学生需要关注、课堂数据能否导出留档”。

## 设计原则

1. 课堂优先：页面要服务 45-90 分钟课堂，不做需要长时间探索的复杂系统。
2. 工作台优先：第一屏直接进入任务和操作，不做营销式首页。
3. 反馈优先：学生操作后必须看到实时检测、错误定位或下一步建议。
4. 数据可扫读：教师看板要像管理后台，少大段说明，多指标、趋势、名单、导出。
5. 渐进复杂：逻辑门、加法器、机器数、存储器、硬件配置逐步升级，不让学生一开始面对完整 CPU。

## 开源项目借鉴点

### CircuitVerse 借鉴

借鉴：
- 电路画布是主角，元件库、端口、导线和仿真反馈围绕画布组织。
- 实验任务和交互式教材可以并排出现。
- 电路状态应有可见的信号反馈。

不借鉴：
- 不开放完整自由电路社区。
- 不做项目分享、公开电路库、多人协作。
- 不把平台改成通用数字电路设计器。

落地到本平台：
- 实验页中间画布更大，左侧关卡/元件，右侧检测/信号。
- 导线、端口、错误点、信号状态用统一视觉语言。
- 每个逻辑门实验显示对应真值表检测。

### MakeCode / PXT 借鉴

借鉴：
- 学习型 IDE 三栏结构：教程/导航、工作区、模拟/反馈。
- 初学者友好的任务步骤与即时结果。
- 操作区不被说明文字淹没。

不借鉴：
- 不引入 Blockly。
- 不做文本代码编辑器。
- 不做扩展市场。

落地到本平台：
- 学生实验页固定为“左路线、中实验、右反馈”。
- 首页改成课程路线地图，而不是介绍页。
- 每关显示目标、预计时间、核心概念、完成状态。

### CREATOR 借鉴

借鉴：
- 计算机体系结构概念需要“状态变化”和“步骤执行”。
- 把抽象理论转换为可观察的寄存器、主存、总线、控制信号变化。

不借鉴：
- 不做完整汇编器和指令集执行环境。
- 不做复杂流水线、缓存一致性、异常中断。

落地到本平台：
- 增加“步骤执行视图”：取指、译码、执行、访存、写回。
- 在第一章概述和存储系统实验中展示数据流、控制信号和状态表。
- 学生每步能看到“发生了什么、哪个部件变化、为什么”。

### Open edX 借鉴

借鉴：
- 教师端与学生端信息架构分离。
- 教师端以课程、班级、学情、内容管理为核心。

不借鉴：
- 不做完整课程 CMS。
- 不做讨论区、评分册、证书、内容发布流程。

落地到本平台：
- 教师首页只放看板。
- 学生导入、CSV 模板、系统配置放在设置页。
- 增加“课堂验收数据”和“首用向导”，让教师第一次使用不迷路。

## 页面设计

### 学生首页：课程路线地图

替换当前偏展示型首页，改为路线地图：

- 顶部：当前进度、下一建议实验、最近一次提交反馈。
- 主区：按章节分组的路线：
  - 第一章 计算机概述
  - 基础逻辑门
  - 加法器与 ALU
  - 存储系统
  - 硬件配置挑战
- 每个关卡卡片显示：状态、最好分、尝试次数、预计时间、核心概念。
- 右侧：AI 助学建议、薄弱点、最近笔记。

验收标准：
- 学生登录后 5 秒内能判断下一步该做什么。
- 不再把大篇课程说明作为首页主体。
- 已完成、进行中、未解锁状态明确。

### 学生实验页：课堂实验工作台

结构参考 MakeCode + CircuitVerse：

- 左侧：关卡路线、元件库、步骤清单。
- 中间：React Flow 画布或硬件配置操作区。
- 右侧：实时检测、信号流、真值表/测试用例、AI 提示。

新增功能：
- 实时数据流检测面板：显示当前输入、期望输出、实际输出、错误端口。
- 真值表小测：逻辑门和加法器关卡显示 2-4 行关键测试结果。
- 步骤执行视图：第一章和存储系统关卡显示“输入 -> 存储 -> 控制 -> 运算 -> 输出”或“地址 -> MAR -> 主存 -> MDR -> 数据总线”。
- 反馈分级：
  - 结构错误：缺少连接、多余连接、端口方向错误。
  - 功能错误：真值表不通过、输出不匹配。
  - 学习建议：下一步先检查哪个部件或信号。

验收标准：
- 学生不提交也能看到基本实时反馈。
- 提交后错误能定位到具体连接、端口或目标。
- 画布区域在 1366x768 分辨率下仍是视觉主角。

### 硬件配置挑战页

保留当前标准版 5-6 个客户案例，做得更像课堂游戏章节：

- 左侧：案例分组，区分“第一章计算机概述”和“存储系统”。
- 中间：客户需求、预算、部件选择。
- 右侧：目标达成评分、瓶颈解释、典型取舍。
- 新增“为什么扣分”解释，不只显示分数。

验收标准：
- 学生能看懂速度、价格、容量三者取舍。
- 教师看板能统计高频瓶颈和典型配置。

### 教师首页：教学驾驶舱

首页只做数据看板：

- 班级选择。
- 学生数、平均完成率、平均分、累计提交。
- 高频错误、硬件瓶颈、风险学生。
- AI 助教报告入口。
- 最近课堂动态。

不在首页放：
- CSV 导入。
- 学生导入模板。
- 大块说明文字。
- 系统设置。

验收标准：
- 教师打开首页第一屏能看到班级真实状态。
- 无数据时显示明确下一步：“去设置导入学生”。
- 有数据时显示可行动结论：“下一节建议讲哪个点、关注哪些学生”。

### 教师设置页

集中放管理动作：

- 创建班级。
- 下载 CSV 模板。
- 导入学生。
- 导出当前班级 CSV。
- 学生密码重置说明。
- 部署/备份提示入口。

验收标准：
- 首页不再承担导入任务。
- 导入失败时显示第几行、哪一列错误。
- 导入成功后能直接跳回教师首页查看数据。

## 功能增量

### 1. 课堂演示数据

新增一个只用于演示/验收的种子脚本或教师端按钮：

- 生成 1 个教师、2 个班、30-50 个学生。
- 生成不同完成率、不同错误类型、硬件配置成绩。
- 数据要能驱动教师看板、AI 助教、CSV 导出。

生产环境默认不自动生成演示数据。

### 2. 首用向导

教师第一次进入时显示 4 步：

1. 创建或选择班级。
2. 下载 CSV 模板。
3. 导入学生。
4. 使用学生测试账号体验一次提交。

向导应可关闭，后续从设置页重新打开。

### 3. 实时数据流检测

基于现有 `circuitSimulation` 和 `challengeCircuitModel`：

- 对当前连接进行轻量模拟。
- 显示关键测试用例通过/失败。
- 显示活动信号线和输出状态。

不新增复杂仿真引擎；先复用现有组合逻辑模型。

### 4. 课堂资源/实验说明微卡片

每个关卡增加简短教学卡：

- 本关概念。
- 常见错误。
- 教师讲解提示。
- 学生自查步骤。

数据可先在前端静态定义，后续再做教师可编辑。

## 视觉系统

### 色彩

保留当前蓝绿色教学科技感，但降低大面积渐变：

- 背景：浅灰蓝或暖白。
- 主色：深蓝用于导航和标题。
- 强调色：青绿色用于通过、连通、完成。
- 警示色：橙色用于待调整。
- 错误色：红色用于结构错误。

避免：
- 大面积紫蓝渐变。
- 过多浮动大卡片。
- 装饰性光斑。

### 布局

- 学生实验页使用固定三栏工作台。
- 教师页使用管理后台式网格。
- 首页使用路线地图，而不是营销式 hero。
- 卡片只用于关卡、学生、指标、弹窗，不做卡片套卡片。

### 组件

- 图标继续使用现有 Phosphor Icons。
- 按钮更紧凑，减少大圆角。
- 状态标签统一：已完成、进行中、未开始、需关注。
- 表格和列表提高信息密度。

## 数据与接口影响

第一阶段尽量不改数据库结构。可复用：

- `student_progress`
- `challenge_attempts`
- `notes`
- 教师 overview
- hardware game summary

可能新增：

- 本地/后端演示数据 seed 脚本。
- 教师首用向导状态，可先存在 localStorage，后续再进数据库。
- 前端静态 `lessonCards` 或 `challengeTeachingNotes`。

## 实施阶段

### 阶段 1：视觉与信息架构

- 学生首页改路线地图。
- 教师首页改纯看板。
- 设置页承接导入、模板、导出。
- 实验页三栏视觉统一。

### 阶段 2：实时检测与教学卡

- 右侧增加实时数据流检测。
- 逻辑门/加法器显示真值表测试。
- 第一章和存储系统显示步骤执行视图。
- 增加每关教学微卡片。

### 阶段 3：课堂验收能力

- 增加演示数据脚本。
- 增加教师首用向导。
- 完善导入错误提示。
- 完整跑通课堂剧本。

## 测试计划

### 单元测试

- 数据流检测能根据当前连接返回通过/失败测试项。
- 教学卡数据覆盖所有关卡。
- 演示数据生成后班级、学生、提交记录完整。
- 教师 overview 能正确聚合演示数据。

### UI Smoke

- 学生登录后首页能看到路线地图。
- 学生进入实验页能看到三栏工作台。
- 改变输入或连接后实时检测区更新。
- 教师登录后首页不出现学生导入大表单。
- 教师设置页能下载模板、导入学生、导出 CSV。
- 硬件配置挑战能显示评分、瓶颈和教师统计。

### 构建验证

- `npm.cmd test`
- `npm.cmd run build`
- `node scripts/verify-ui.mjs`

## 风险与控制

- 风险：`App.jsx` 已经偏大，继续堆 UI 会难维护。
  - 控制：新增较大视图时拆出组件，至少把路线地图、实时检测、教师设置区独立。
- 风险：视觉重构影响现有课堂流程。
  - 控制：先改信息架构和样式，不改判题核心。
- 风险：实时检测和提交判题出现不一致。
  - 控制：实时检测复用现有 simulation/validation 模块，不另写一套规则。
- 风险：开源项目借鉴变成范围膨胀。
  - 控制：只借鉴交互结构和教学功能，不复制完整平台。

## 验收定义

这次升级完成后，平台应满足：

- 教师可以用演示数据在 3 分钟内展示平台价值。
- 学生可以从首页直接进入下一实验，不需要老师反复解释页面。
- 实验页能实时告诉学生“哪里错、为什么错、下一步查什么”。
- 教师首页能回答“这个班哪里卡住，下一节课讲什么”。
- 课堂使用流程从登录、导入、实验、查看、导出完整跑通。
