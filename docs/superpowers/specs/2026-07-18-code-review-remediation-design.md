# 代码审核问题定向修复设计

**日期：** 2026-07-18

**目标：** 在保持现有 API 路径、SQLite 数据和主要界面结构兼容的前提下，修复 2026-07-18 代码审核发现的发布阻断、课堂闭环、授权、安全和测试覆盖问题。

## 1. 范围

本轮修复包含：

- 恢复共享浏览器 QA 启动器，使 UI、3D、性能和课堂门禁可执行。
- 打通真实学生实验 UI 到课堂提交服务的 `clientSubmissionId` 幂等链路。
- 修复课堂结束时 `LabPage` 条件 Hook 调用问题。
- 对作业详情、提交列表、草稿、提交、分析和课堂回放强制执行资源归属校验。
- 将请求日志和 CSRF 校验移动到全部业务路由之前，并采用严格同源判断。
- 停止把初始密码写入 `profile_json`；保留可迁移的密码状态标记。
- 修复登录失败窗口过期后限流失效及失败记录无界增长。
- 把课堂 Playwright 门禁改成真实浏览器操作核心路径。

本轮不包含：

- 故障注入、任务变体和优化指标的新产品集成。
- 全量重构 `App.jsx`、认证系统或数据库访问层。
- 改变现有公开 API 路径、课堂状态枚举或作业表结构。

## 2. 架构与兼容性

### 2.1 中间件顺序

`loadSession`、请求日志和 CSRF 校验在所有课堂、作业及传统 API 路由之前注册。CSRF 校验将请求 `Origin` 或 `Referer` 解析为 URL，并比较协议、主机和端口；没有配置 `PUBLIC_BASE_URL` 时，使用请求自身的协议与 `Host` 作为期望来源。保留无 `Origin`/`Referer` 的非浏览器同源客户端兼容性。

### 2.2 授权边界

路由层只负责解析参数和响应；资源所有权由 service 或专用查询函数校验：

- 教师访问作业时，作业对应班级必须由当前教师拥有。
- 学生访问、保存或提交作业时，必须属于作业对应班级，且学生可见接口只接受已发布作业。
- 教师查看学生作业分析时，只返回指定且由该教师拥有的班级数据；未指定班级时仅返回该教师所拥有班级中的数据。
- 教师查看课堂回放前，先验证课堂场次属于当前教师，再验证学生属于该场次。

未授权资源统一返回 404，避免通过 ID 枚举确认资源存在。

### 2.3 课堂提交数据流

`App.jsx` 保留普通练习保存入口，但在课堂任务活动时将标准化证据交给 `classroomSession.submit()`。该 Hook 生成 UUID、持久化待提交请求、调用现有 `/api/student/attempts`，并用服务端返回的 `current_stage_index` 立即更新当前阶段、奖励和完成状态。非课堂练习继续使用原有提交形状。

`LabPage` 接收合并后的课堂视图模型和提交函数，不增加一组零散布尔属性。课堂暂停时提交入口和键盘状态变更不可用；课堂结束结算渲染发生在所有 Hook 调用之后。

### 2.4 密码数据

学生导入只将密码哈希写入 `password_hash`。`profile_json` 不再保存 `initialPassword`，改用 `mustChangePassword: true`。学生成功修改密码后将其更新为 `false`，并记录 `passwordChangedAt`。迁移不尝试恢复或显示已有明文密码；应用读取用户资料时过滤遗留 `initialPassword` 字段，备份前执行兼容清理，确保新备份不包含该字段。

### 2.5 登录限流

失败窗口到期后，下一次失败从新窗口的第 1 次开始。成功登录清除记录；定期或按请求机会清理过期记录，并设置合理的 Map 数量上限，避免随机用户名造成内存增长。测试使用可注入时钟或独立纯函数，避免真实等待。

## 3. 错误处理

- 授权失败返回 404；未登录和角色不符继续返回 401/403。
- CSRF 拒绝返回 403 和稳定的 JSON 错误消息。
- 课堂提交的结构化错误码保持现状，不改变客户端重试语义。
- 自动刷新失败保留已有视图数据并显示错误状态。
- QA 启动失败必须以非零状态退出并保留明确的脚本/阶段信息。

## 4. 测试策略

所有行为修复遵循 red-green TDD：

1. `node --check` 回归覆盖共享 QA 启动器语法。
2. React 纯状态或渲染测试覆盖课堂提交委派、立即阶段推进和结束结算 Hook 顺序。
3. 双教师、双班级、双学生 API 测试覆盖作业详情、提交列表、草稿、提交、分析和课堂回放越权。
4. API 测试验证课堂/作业状态变更会经过 CSRF 和请求日志中间件。
5. 数据库测试验证新导入、资料响应和备份内容不含 `initialPassword`。
6. 可控时钟测试验证限流窗口过期后重新计数且旧记录被清理。
7. `qa:classroom` 使用一个 Chromium、教师和学生两个 context，通过页面按钮完成创建、开始、发现、进入、提交、暂停、恢复和结束；API 只用于隔离数据准备，不代替被验收的用户操作。
8. 最终执行单元/API 测试、生产构建、资源预算、150 人课堂负载、UI、3D、性能和课堂 Playwright 门禁。

## 5. 验收标准

- 四个共享浏览器 QA 命令均能启动并退出 0。
- 学生从 UI 提交课堂阶段后，服务端状态与 HUD 在同一交互周期更新，重复请求保持幂等。
- 任意教师或学生不能读取、提交或分析非所属班级的作业和课堂回放。
- 课堂和作业写操作经过 CSRF 校验并进入结构化请求日志。
- 新建及清理后的数据库、用户响应和备份均不含明文 `initialPassword`。
- 登录限流跨窗口持续有效，失败记录有界。
- 完整测试、构建、资产、负载和浏览器质量矩阵通过。
