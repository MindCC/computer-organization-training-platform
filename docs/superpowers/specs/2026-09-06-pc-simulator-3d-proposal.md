# 参考装机模拟器的教学 3D 改进方案（2026-09-06 已批准）

> 2026-09-07 实施更新：第一阶段已完成；第二阶段首套 Blender 源模型、GLB 加载与侧板/固定/散热/接线检查已接入。当前实际交付和重新生成方法见 [资产规范](../../../prototype/docs/blender-asset-contract.md)。下文“当前基础与缺口”和实施前环境描述保留为方案提出时的记录。

目标：学生能辨认真实部件，理解安装位置、顺序与启动条件，在普通机房电脑中完成一台通用主机的装配。参考 PC Building Simulator 的部件呈现、分步装配和工作台反馈，保留本项目明亮工作台、深蓝导航与青绿状态色。

## 当前基础与缺口

现有 Three.js 工作台已支持 CPU/内存/硬盘/独显拖放、错插拒绝、拆卸、开机检查、无 WebGL 替代操作。CPU、内存等使用程序化组合模型；主板与电源预装；教学模式自动处理存储接线。现有截图中部件偏暗，标签集中重叠，机箱内部和待装部件辨认困难。装配状态只保留在当前组件生命周期。

生产分包还有确定故障：dist 的 Three.js 模块在 WebGL2 可用环境抛初始化 ReferenceError，概述页退回静态视图。此问题是第一阶段先决条件，不能通过换模型解决。

## 三种路线

| 路线 | 优点 | 代价 | 判断 |
|---|---|---|---|
| 继续全部程序化建模 | 容易修改、资源小、无额外制作工具 | 主板插槽、机箱结构、细节质感维护困难 | 适合交互原型 |
| Blender 模型 + Three.js 交互 | 便于控制真实比例、部件拆分、UV 与材质，同时保留现有网页系统 | 需要制作、导出和性能检查流程 | 推荐 |
| 转向完整游戏引擎制作 | 适合更完整的经营、维修与环境系统 | 重写和网页集成成本高，本项目机房资源约束更难把控 | 当前阶段不建议 |

## 推荐设计

### 第一阶段：可靠、清晰的现有装机工作台

1. 修复生产循环分包，在实际 dist 中加载概述与装机模型，捕获控制台错误、页面错误和资源加载失败；要求 WebGL2 可用时 canvas 正常创建。
2. 工作台默认使用能看到主板和插槽的三分之四视角；独立提供 CPU、内存、显卡、硬盘近景和复位。选中部件后相机平滑聚焦，尊重减少动画设置。
3. 常态只显示当前部件与目标插槽标签，避免所有标签互相遮挡。拿起时显示目标轮廓和半透明安装预览，错误目标有明确原因与回位反馈。
4. 保留鼠标拖放与键盘替代路径，修正台面、灯光和材质，使金属外壳、PCB、电气接口能被识别；安装成功表现为沿固定方向插入及状态确认。
5. 记录按学生和订单隔离的本地装配草稿；配置变动清除受影响部件的安装与开机状态。草稿只用于恢复操作，不作为服务端成绩证据。

这一阶段可以使用现有模型完成，验收不依赖 Blender 是否已安装。

### 第二阶段：Blender 资产与完整装配步骤

制作一套原创通用教学主机：机箱侧板、主板、CPU、CPU 散热器、内存、独显、SATA SSD、电源。先做一套，使用颜色、标签与后续变体扩展型号，不建立数百个品牌型号库。

流程：打开侧板 → 安装主板/电源 → CPU → 散热器 → 内存 → 按配置安装独显 → 存储 → 连接必要接口 → 开机自检。顺序由具体前置条件约束，允许没有依赖关系的步骤自由选择。连接步骤使用端点选择和预制线形，不模拟软线物理；螺钉用简化固定动作，不做逐颗物理旋拧。

开机失败具体说明 CPU/内存未安装、散热器缺失或必要连接未完成；成功后继续使用已有订单评分。核显始终是配置能力，不出现可安装的“核显卡”。散热与供电只实现明确的教学规则，不冒充真实电气或温度仿真。

### Blender 与网页的接口

- Blender 保存 .blend 源资产，导出本地 GLB；模型、贴图均随项目部署，课堂运行不依赖外部素材站。
- 可操作部件为独立命名节点，统一尺寸和轴向，原点设在安装参考位置；主板 CPU/DIMM/PCIe 等锚点通过命名节点描述。
- 使用 glTF 可支持的 PBR 材质，复杂节点先烘焙成贴图；避免把 Blender 渲染画面直接当作浏览器效果承诺。
- Three.js 负责 GLB 加载、拾取、相机、轮廓/预览、动画与资源释放；React/纯状态函数负责前置条件、安装/拆卸和开机状态。
- 加载失败有可见错误及现有教学替代路径；保留程序化模型作为开发和加载降级来源。

### 建议性能预算与验收

第二阶段新增模型预算先以首套 GLB 与贴图合计 ≤5MB、可见模型 ≤100k 三角面、贴图通常 1K/重点部件至多 2K 为设计上限；最终以实际 GPU 内存和帧率测量调整。这是拟定预算，尚未有模型验证结果。

继续保持现有首屏 JS 与 3D JS 分包预算；模型懒加载，采用共享材质和受限像素比。1366×768 下场景占主视区；390px 布局无横向溢出。目标机上帧率至少 30 FPS；至少完成十次进出与资源释放测试。

覆盖正常装配、错误位置、前置条件不满足、取消拖动、拆卸依赖、切换配置、刷新恢复、核显配置、断网加载本地资产、WebGL 不可用、生产模块加载。新设计不得以仅 Vite 开发环境通过作为完成依据。

## 本轮实施边界与选择

建议先实施第一阶段，同时准备 Blender 节点/材质规范；随后制作第二阶段首套资产和扩展状态机。实施需要先确认这个方向，避免直接投入完整模型库或重写整站。当前仅检查了 PATH 和常见安装目录，未发现可调用 Blender；尚未安装或下载任何建模工具及第三方模型。
