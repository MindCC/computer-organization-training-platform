# 计算机组成原理实训平台：开源项目借鉴与分阶段建设方案

日期：2026-09-07。状态：详细建议稿，供后续实施确定范围；本次只编写文档。

## 1. 建设结论与目标

建议以现有平台为主体，借鉴 OpenMAIC 的课程组织方式、CircuitVerse/Logisim 的电路实验交互、Ripes/emulsiV 的处理器可视化、Wrench 的参数化出题，再增强现有 Blender + Three.js 装机工作台。

最终形成一条教学主线：**认识硬件 → 搭建电路 → 观察指令执行 → 排查整机故障 → 提交可复核的实验成果**。教师围绕同一任务查看进度、错误和成果，学生围绕同一任务完成操作、解释和复盘。

本方案中的模块、接口、表名、性能新增指标均为建议设计，不能理解为已实现能力。外部项目事实以第 3 节所列仓库为依据；后续功能设计是结合本项目提出的方案。

### 1.1 可观察的教学成果

| 对象 | 当前体验基础 | 建设后的目标 |
|---|---|---|
| 学生 | 关卡、电路、装机、笔记和项目反思 | 能回答“操作改变了什么状态、为什么结果错误、如何用实验验证” |
| 教师 | 开课、学情、课程审核、小组评价 | 能定位某一步的共同错误，查看学生成果及必要过程，发布有针对性的补练 |
| 课程作者 | 固定关卡和有限导学动作 | 用结构化步骤组合讲解、操作、预测题、检查点和项目里程碑 |
| 平台维护者 | 多个已有业务模块 | 用版本化任务和统一判定结果连接模块，同时保留各模块的专用模拟器 |

### 1.2 范围边界

沿用 React、Vite、Express、SQLite、React Flow、Three.js 和 Blender 资产流程。新增 CPU 模块使用 SVG/React 展示数据通路，3D 继续用于可识别的实体硬件。首轮不引入完整 OpenMAIC 服务栈、桌面模拟器、任意代码执行、多人实时协同编辑或科研级周期精确仿真。

真实教室硬件测试仍是最终部署验收事项；用户此前排除的实机验证不纳入本次方案执行承诺。自动化验证可以先完成，但不能将开发机结果视为所有教室设备的结果。

## 4. 产品结构与典型课堂

### 4.1 学生侧

继续使用课程地图。进入任务后，统一显示任务目标、当前步骤、操作区、检查结果及复盘入口。电路、CPU、3D 保留各自合适的工作台；任务容器负责上下文、进度和提交。

步骤类型分为：讲解、观察、预测、操作、验证、反思。讲解的“继续”只代表阅读确认；操作必须满足检查条件，才能标记实验通过。预测题在揭示本次答案前冻结该次回答，随后可以创建新的练习尝试。

### 4.2 教师侧

在现有课程工作台增加课程版本、步骤编辑、学生视角预览和验证报告。课堂看板增加“当前卡在哪一步”“主要错误原因”“需要复核的提交”。点击学生可查看相关实验状态和关键操作时间线，而非默认加载整班全部日志。

教师发布流程：选择模板 → 调整目标/参数/步骤 → 预览并运行参考解 → 发布课程版本 → 选择班级开课。AI 生成位于草稿编辑内部，人工编辑与本地模板始终可用。

### 4.3 首个端到端样板：一条加法指令如何完成

建议设计为约 45 分钟课堂，时间为教学安排建议。

| 环节 | 时间 | 学生行为 | 验收证据 |
|---|---:|---|---|
| 硬件定位 | 5 分钟 | 在概述场景识别 CPU、内存、总线并回答职责题 | 选择结果与职责回答；点击本身不证明掌握 |
| 电路实验 | 10 分钟 | 完成加法器并验证进位 | 规范化电路产物、公开/隐藏用例判定 |
| 指令执行 | 15 分钟 | 预测 PC/ACC，再单步执行 LOAD、ADD、STORE | 预测回答、模型版本、输入程序与服务端复算 |
| 故障解释 | 10 分钟 | 定位错误数据/错误地址，修改后重跑 | 修改前后状态差量、关键失败用例 |
| 个人复盘 | 5 分钟 | 解释取指和取数的地址来源 | 反思文字关联本次实验记录 |

该样板先连接已有硬件概述、电路和新 CPU 模块；3D 维修工单作为后续独立课程包，不要求学生在一节课内完成所有功能。

## 5. 课程协议与执行机制

### 5.1 最小结构化课程协议

建议命名 CourseSpec v1。它是受约束的 JSON 文档，不是可执行脚本。课程显示内容和服务端评分配置分别存储、分别序列化。

```json
{
  "schemaVersion": 1,
  "courseKey": "instruction-addition",
  "revision": 1,
  "title": "追踪一次加法",
  "objectives": ["区分取指地址与操作数地址", "解释 ACC 的变化"],
  "requirements": {"cpuModel": "edu16-acc@1"},
  "steps": [
    {
      "id": "predict-acc",
      "kind": "prediction",
      "workspace": "cpu",
      "instruction": "执行 ADD 后 ACC 应是多少？",
      "entryActions": [{"type": "cpu.focus", "target": "ACC"}],
      "checkpointKey": "prediction-1"
    },
    {
      "id": "execute-add",
      "kind": "experiment",
      "workspace": "cpu",
      "instruction": "单步运行并核对预测。",
      "entryActions": [{"type": "cpu.loadPreset", "presetId": "addition-demo@1"}],
      "checkpointKey": "execution-1"
    }
  ]
}
```

示例只说明结构。`checkpointKey` 在服务端解析为评分器和私有测试；客户端不会收到答案、故障真值或完整隐藏用例。预设加载只在步骤首次进入时发生，恢复和回放不再次重置实验。

首次只支持线性步骤和“失败后重试”，避免立即实现任意分支脚本。初始建议上限为每课程 24 步、每步 4 个进入动作、规范化课程 JSON 256 KiB；超限返回明确校验错误，实际调整依据样板课测量。

### 5.2 能力注册表

每个动作登记参数类型、目标模块、前置条件和执行函数。发布时验证动作存在、部件/预设引用有效、模块版本可用；旧版本依赖不可静默切换到新行为。

| 类别 | 首批动作示例 | 完成条件 |
|---|---|---|
| 通用 | showHint、focusPanel | 阅读确认，仅记参与状态 |
| 3D 导学 | highlightPart、setXray | 复用既有语义；知识判断另设题目 |
| 电路 | circuit.loadTemplate、circuit.focusPort | 模型校验及测试结果 |
| CPU | cpu.loadPreset、cpu.focus | 程序执行结果及预测题 |
| 装机 | assembly.loadWorkOrder、assembly.focusSocket | 服务端验证后的装配/诊断结果 |

界面播放动作、学生操作意图和评分结果是三个不同对象。AI 可以生成允许的课程动作；学生可以请求合法操作；只有服务端判定器可以产生正式通过记录。

### 5.3 生命周期、恢复与回放

复用课堂 draft → live ↔ paused → ended 状态。任务进度只管理步骤与尝试，不再复制课堂暂停状态；每次提交读取所属课堂状态，按已有补交规则处理结束后的请求。

课程草稿经验证发布为不可变版本；修改通过“复制为下一版本”完成。已开课实例和已有学生尝试始终引用原版本。课程存档只影响新建入口，不删除历史证据。

采用“当前状态快照 + 有界关键操作记录”，无需将整个平台改为全量事件溯源。记录接线、参数修改、程序提交、检查、提示、装入/拆出等语义动作，不记录逐帧动画或鼠标轨迹。

练习可先本地运行；网络异常显示未同步，正式评分保持待提交。服务端确认后方可显示已提交。恢复时读取服务端快照及已确认序号；本地缓存只补回尚未确认的草稿，不能恢复通过或开机评分状态。

多标签页使用 `baseRevision` 乐观并发控制：冲突返回 409 并保留本地草稿供比较，不做无提示的覆盖。回放默认只读，不触发重新提交、发分或课堂操作。

## 6. CPU 执行实验室

### 6.1 模型选择

建议第一版采用 **EDU16-ACC 教学机**，与现有 PC/MAR/MDR/IR/ACC 讲解保持一致。它是本项目教学模型，不宣称兼容 RISC-V 或真实 CPU。

上一版概览中的 BEQ 和通用寄存器表达不直接沿用：累加器模型使用 JZ，避免两种体系混杂。若课程明确要求 RISC-V，应改选标准 RV32I 子集并单独确定编码和教材映射。

| 项目 | 第一版确定的建议语义 |
|---|---|
| 数据 | 16 位，存储为 0–65535；有符号显示采用二进制补码解释 |
| 存储 | 256 个 16 位字，按字寻址，地址范围 0–255 |
| 寄存器 | PC、MAR 为 8 位地址；IR、MDR、ACC 为 16 位 |
| 指令字 | 高 4 位操作码、中 4 位保留为 0、低 8 位地址；非法编码陷阱停止 |
| 运算 | LOAD、STORE、ADD、SUB、AND、OR、JZ、JMP，加 HALT 共 9 条 |
| 操作数 | LOAD/算术/逻辑读取 M[address]；STORE 写 ACC；JZ 在 ACC=0 时跳转 |
| PC | 正常取指后加 1 并按 256 取模；跳转覆盖下一取指地址；显式展示回绕 |
| 溢出 | ADD/SUB 按 16 位截断，显示原始数学结果及截断提示；第一版无溢出异常 |
| 执行限额 | 每次自动运行最多 1000 条已提交指令，超限暂停并说明可能循环 |

操作码建议固定：0=HALT，1=LOAD，2=STORE，3=ADD，4=SUB，5=AND，6=OR，7=JZ，8=JMP；HALT 低位必须为 0，其余未定义操作码非法。简易汇编输入支持上述助记符、地址及注释，校验失败指向行号。第一版不需要外部编译器或运行本机程序。

### 6.2 执行内核与展示分离

纯函数接受模型状态和操作，输出下一状态及变化记录。支持单微步骤、单指令、运行到暂停/结束和重置。微步骤是教学分解，不等同硬件时钟周期，不能用动画步数计算真实 CPI。

核心状态包含 memory、PC、MAR、MDR、IR、ACC、phase、instructionCount、halted 和 trap。状态差量包含 changes、activeTransfers、controlSignals、explanationKey。CPU 模块直接依赖数值状态，不依赖 React、DOM、Three.js 或动画完成回调。

示例程序：地址 0 为 LOAD 16，1 为 ADD 17，2 为 STORE 18，3 为 HALT；M[16]=6、M[17]=1。应得到 ACC=7、M[18]=7。增加零值、溢出、条件跳转成立/不成立、非法操作码、循环限额和 PC 回绕用例。

服务端用同版本内核复算程序和初始数据。浏览器传来的寄存器最终值仅供诊断，不能直接作为得分。复算证明程序结果可重现，不证明学生独立完成；教学掌握仍结合预测题、参数变体和解释题判断。

### 6.3 页面布局与操作

1366×768 下：左侧程序及当前行，中间数据通路，右侧寄存器和检查结果，底部可展开内存与时间线。每一步高亮变更前后值，同时保留文本说明；不只用颜色传递状态。

控制条提供“微步”“执行一条”“运行”“暂停”“重置”。预测题出现时自动运行暂停，提交预测后继续。历史步查看不修改当前执行；选择“从此状态重新练习”时创建新尝试。窄屏改为程序/通路/状态分页，减少动画模式直接显示数值变化。

### 6.4 第二阶段以后

先完成单核模型与三个样板程序，再考虑流水线。流水线必须明确级间寄存器、数据冒险、停顿、转发、分支冲刷及测试，不把五段彩色动画命名为流水线模拟。标准 ISA、缓存命中率和 CPI 实验各自作为独立后续需求。

## 7. 电路实验升级

### 7.1 模板和子电路

第一步提供模板版本、派生关系和保存点。学生改动不会修改教师模板；教师可看到元件/连线/参数的变更。功能题按输入输出判定，允许不同正确拓扑；只有明确要求指定器件或布线的题目才检查结构约束。

第二步增加子电路：子电路定义包含 id、version、输入/输出端口、位宽和内部模型。实例引用固定版本。端口名在版本内稳定；递归引用、重复端口、位宽不匹配在运行前拒绝。建议初始嵌套上限 3 层、展开上限 200 个元件，后续按性能测量调整。

### 7.2 信号轨迹

先做离散输入序列采样：学生选择最多 8 个探针，运行最多 256 个样本，查看输入和输出变化。组合逻辑样本只在稳定计算结束后记录；出现 unknown/error 保留状态，不强转为 0。

该功能称“离散信号轨迹”，不宣称模拟传播延迟、毛刺或真实纳秒时序。加入寄存器和时钟时，需另行定义边沿、复位、初态和组合逻辑稳定顺序，再扩展为同步时序实验。

### 7.3 错误诊断与评分

失败结果包含 caseId、错误类别、相关端口、公开输入、预期/实际值和分级提示。隐藏测试只返回错误类别及有限定位信息。常见类别包括未连接、多驱动、位宽不符、无效回路、功能结果错误和结构约束不满足。

示例评分建议：功能正确 70%、指定结构约束 20%、解释 10%；每种任务可调整。没有结构要求时相应分值移入功能项。提示默认记录使用情况，不自动扣分；若考试任务需要扣分，发布前明确告知并冻结规则。

### 7.4 与 CPU 的连接边界

第一轮通过共同实验题和产物引用连接“加法器”和“CPU ADD”，CPU 仍使用经过测试的参考算术内核。后续可新增“学生 ALU 接入 CPU”模式，但必须限定运算接口、位宽和求值上限，服务端以同一电路产物复算，不能用页面通过徽章代替部件行为。

## 8. 参数化作业与自动判定

升级现有 generateVariant：固定 generatorVersion、任务版本和 seed，生成实际不同的合法题目。相同三者必须产生相同题目；生成后用参考解先验证可解，失败则标记模板不可发布或退回已验证基础题，并记录原因。

| 类别 | 可变内容 | 保持等难度的约束 |
|---|---|---|
| 电路 | 输入向量、指定故障、允许器件参数 | 保持考查点、器件规模和故障数范围 |
| CPU | 初始数据、操作数地址、短程序常量 | 保持指令数/分支类型和目标知识点 |
| 装机 | 合法配置、缺失连接、故障位置 | 保持故障类别与检查步骤预算 |

同一课堂可选择全班同题、按小组或按学生分配。seed 在服务端实例创建时生成并保存，不从姓名等个人信息推导。重试沿用当前题目；“再练一题”才创建新实例。隐藏用例即使可由公开模型推测，也仍留在服务端，不能将隐藏测试等同防作弊保障。

统一判定输出建议：passed、score、rubricVersion、reasonCodes、publicFeedback、artifactId、evaluationId。评分器登记版本并实施输入大小、运行步数与展开规模上限，结果用于复盘、教师审核和学情聚合。

## 9. 3D 故障工单与 Blender 精修

### 9.1 工单结构与流程

工单包括症状、初始装配状态、允许检查项、预算/约束、目标状态、评分规则与教师解释。客户端只接收可见症状和可操作状态，故障答案由服务端保存。

学生流程：阅读症状 → 提出初步判断 → 检查 → 拆装/接线 → 自检 → 提交结果与原因。工作台保持 3D 为主，侧栏显示工单和检查结果。检查提供“供电检查”“内存检查”“存储连接检查”等教学动作，每项返回由模型状态推导的结果。

| 首批工单 | 症状示例 | 现有规则可复用点 | 通过条件 |
|---|---|---|---|
| CPU 供电遗漏 | 主机未通过启动自检 | EPS 接线和部件依赖 | 接好 CPU 供电并再次验证 |
| 内存未完成安装 | 内存检查失败 | 内存插槽、装入/移除规则 | 正确安装当前选定内存 |
| 系统盘连接遗漏 | 存储检查失败 | SATA 数据和供电两类连接 | 两类连接均有效 |
| 更换 CPU 后散热器失效 | 散热安装检查未通过 | CPU 更换导致散热器重新安装 | 正确匹配并完成散热器安装 |
| 电源更换后的接线恢复 | 多项供电检查失败 | 拆电源清除连接规则 | 恢复全部必要连接并验证 |

以上是教学故障模型，不声称复现所有真实 BIOS、厂商错误码、风扇行为或热力学现象。首批单故障，稳定后增加两种故障组合；生成器不得分配当前部件或工具无法修复的问题。

建议评分：结果正确 60%、必要检查证据 25%、解释 15%。练习模式不因慢速操作扣分，避免把熟练鼠标使用当作理解程度。

### 9.2 Blender 资产工作清单

继续遵循现有 [资产合同](../../../prototype/docs/blender-asset-contract.md)。每个精修资产同时保留可编辑源和网页 GLB，节点/锚点与业务映射一致。

1. CPU：强化方向三角、插座结构和接触位置，近景仍可辨认方向。
2. 内存：强化金手指、缺口和插槽卡扣；装入预览不遮挡目标。
3. 主板：区分 24-pin、CPU 8-pin、CPU_FAN 和 SATA 接口，热点名称对应现有规则。
4. 电源与线缆：制作可识别插头，用简化曲线表达连接，正确连接后更新路径；不增加软线物理。
5. 散热器与侧板：完善底座、风扇及开合轴心，动作动画与规则状态分开。
6. 材质：优先粗糙度、金属与塑料区分及少量烘焙细节；依现有预算控制模型和纹理。

Blender 负责几何、材质、锚点及动作素材；Three.js 负责相机、拾取、预览和播放；业务规则负责兼容性、安装依赖和评分。相机动画完成与否不能决定是否安装成功。

## 10. OpenMAIC 思路在教师备课中的落地

### 10.1 两阶段生成

阶段一只生成目标、大纲、预计时长和模块选择。教师修改后，阶段二按步骤补充讲解、题目、受支持动作及评价建议。重新生成某一步不覆盖其他已编辑步骤，显示修改差异后保存草稿。

复用现有 AI 客户端和本地 fallback。生成任务持久化 queued/running/succeeded/failed/cancelled 状态以及已经完成的步骤。恢复从已完成阶段继续；超时或取消保留可编辑草稿。早期使用固定流程调用模型即可，不要求多个自主 agent 互相讨论。

### 10.2 生成内容的验证

模型输出经 CourseSpec 校验、动作白名单、资源引用检查，再执行模板参考解验证。模型可以建议题目说明和评价文字，但评分器 ID、版本和参数必须来自受支持集合。任意脚本、模型自创工具、无效部件名均拒绝并定位到步骤。

第一版素材输入限定为教师主动填写的课程文本和已维护的素材目录。完整文档导入、网络抓取、音视频生成列为后续扩展；不默认上传学生姓名、成绩或操作记录到模型提供商。

生成应设置可配置超时、输出大小和单次课程调用上限；保存耗时、成功步骤与消耗信息（供应商可提供时）。供应商失败回到已有本地模板；不阻断现有课堂与手工备课。

### 10.3 OpenMAIC 兼容性策略

先完成本项目原生草稿生成。未来若需要导入 OpenMAIC 课程，再固定一个上游版本及其实际导出格式，用样本文件做映射表与兼容性测试。只接受支持的文本、题目及动作；未知内容提供逐项诊断，阻止带有未处理必需步骤的课程发布。不承诺无损导入任意 OpenMAIC 课程或直接兼容全部 SDK。

## 11. 数据、API 与代码接入建议

### 11.1 数据实体

以下为建议新增实体，表名在实施时与现有迁移约定一致；不把所有新表一次性加入。

| 实体 | 主要字段/约束 | 与现有数据的关系 |
|---|---|---|
| course_versions | courseKey、revision、schemaVersion、publicSpec、privateAssessment、sourceDraftId、contentHash；key/revision 唯一 | 从已有课程草稿发布；现有已发布课程可适配为 v1 |
| lab_runs | studentId、sessionId、courseVersionId、stepId、attemptNo、modelVersion、generatorVersion、seed、stateRevision、snapshot | 关联现有课堂和学生；课堂生命周期仍由 classroom_sessions 决定 |
| lab_events | runId、eventId、serverSequence、type、payload、serverTime；run/eventId 唯一 | 保存必要操作；学生身份从登录会话获得 |
| lab_artifacts | runId、kind、schemaVersion、content、contentHash | 保存电路、程序、装配配置等可重算产物 |
| lab_evaluations | artifactId、rubricVersion、score、passed、reasonCodes、createdAt | 追加判定；已有成绩展示通过适配器聚合 |
| generation_jobs | draftId、stage、status、completedSteps、errorCode、providerMeta | 在 AI 阶段新增，复用已有草稿和权限 |

小组任务仍沿用 team_projects 和成员表。个人反思关联个人产物或明确引用小组产物；记录 actorStudentId 只用于追溯操作，不将共用成果自动等同每个人独立掌握。

### 11.2 接口草案

| 建议接口 | 输入重点 | 行为 |
|---|---|---|
| POST /api/teacher/course-drafts/:id/validate | 草稿 revision | 返回步骤错误与参考解检查结果 |
| POST /api/teacher/course-drafts/:id/publish | expectedRevision、requestId | 扩展已有发布接口，原子保存课程版本和项目关联 |
| POST /api/teacher/course-versions/:id/fork | 新版本说明 | 新建可编辑草稿，保留谱系 |
| POST /api/student/lab-runs | 合法课堂/步骤引用、requestId | 从已发布版本创建或返回运行实例，服务端确定 seed |
| GET /api/student/lab-runs/:id | 无 | 返回授权可见快照、已确认序号及状态 |
| POST /api/student/lab-runs/:id/events | baseRevision、batchId、events | 验证操作、按事务写入、返回新序号 |
| POST /api/student/lab-runs/:id/evaluate | artifact、clientSubmissionId | 服务端复算、保存判定并适配现有进度 |
| GET /api/teacher/lab-runs/:id/review | 游标/筛选 | 校验班级归属，返回产物、结果和分页事件 |

上述是建议路径，不代表新增接口已经存在。无权读取资源沿用项目现有 404 风格；格式错误 400、版本冲突 409、负载过大 413、限流 429。客户端不得提交 teacherId/studentId 来选择身份，也不得上传 passed/score 覆盖正式成绩。

幂等键在同一逻辑请求重试时复用；修改产物后的新提交使用新键。相同键和相同规范化请求返回原结果；相同键而内容不同返回冲突。核对幂等重试应先于陈旧 baseRevision 检查，使“服务端成功但客户端丢响应”的重试可恢复。参考此前项目提交重试修复，避免再出现提交后丢失键或下一次误复用的问题。

### 11.3 写入规模与保留策略

本地动画无需等待网络。语义事件合并为小批次，建议每 3 秒或 20 条提交一次；每批最多 50 条/64 KiB，每个尝试先设 500 条关键事件上限。CPU 逐微步运行可保存程序、输入、执行区间和检查点以重算轨迹，无需每微步落库。

超过事件预算保留当前产物和判定能力，并明确显示“过程记录已截断”，不能伪造完整回放。课堂暂停期间待发送操作按服务器状态和既有政策处理，客户端时间不能作为暂停前操作的可信证明。

建议详细过程默认保留 90 天，课程结束支持导出；正式成绩、产物和判定按学校课程留存政策配置。清理作为后续可配置功能，不由本次文档授权删除已有数据。性能测试需同时覆盖事件写入、评分和教师轮询，不能只测原有读接口。

## 12. 分阶段实施与交付门槛

以下工作量是单名熟悉项目的开发者、按现有规模做出的粗估，包含本阶段开发和测试，不是日期承诺。CPU 模型或素材范围改变时重新估算；教师审阅和真实教室试点时间另计。

| 阶段 | 优先级/估算 | 交付内容 | 完成判据 |
|---|---|---|---|
| A：最小课程协议 | P0，4–6 人日 | 旧导学适配、CourseSpec 校验、版本发布、一个现有电路步骤接入 | 旧课程可读；新版本不改变旧实例；非法动作不能发布 |
| B：证据与恢复 | P0，4–6 人日 | 运行实例、产物、评分适配、幂等与冲突、教师单人复核页 | 断网重试不重复计分；越权拒绝；快照可恢复但不自授通过 |
| C：CPU 样板 | P1，8–12 人日 | EDU16 内核、单步 UI、三套程序、预测题、服务端复算 | 指令边界测试通过；样板课端到端完成；无动画驱动评分 |
| D：电路深化 | P1，7–10 人日 | 参数化题目、模板派生、子电路、离散轨迹 | 等价正确电路可通过；无效层级拒绝；同 seed 可重现 |
| E：3D 工单 | P1，6–9 人日，另加美术 3–6 人日 | 五种基础工单、检查与复盘、重点模型精修 | 每单可复算；错误修复不通过；恢复必须重新自检 |
| F：AI 备课增强 | P2，5–8 人日 | 两阶段生成、逐步重生成、草稿差异、持久化任务、fallback | 失败保留草稿；未支持动作被拦截；只生成草稿 |
| G：整体验收 | P0，3–5 人日 | 跨模块回归、迁移演练、混合负载、使用文档 | 既有质量门禁和新增关键旅程通过 |

完整范围约 **37–56 开发人日，加 3–6 美术人日**。阶段 A+B+C 是建议首批交付，约 16–24 开发人日；先得到一套真实可用的“课程—执行—评价”样板，再依据课堂反馈细化 D/E/F。

依赖关系：A → B → C；D/E 在 A+B 完成后接入统一机制；F 依赖 A 的稳定协议；G 在每阶段有局部验证，最终再做联合验收。OpenMAIC 外部格式导入、流水线和学生 ALU 驱动 CPU 不在上述估算内。

### 12.1 建议拆分的首批变更

1. A1：旧课程兼容适配及 schema；用旧草稿样本证明无损读取。
2. A2：不可变版本与发布事务；验证版本衍生和重复发布请求。
3. B1：实验产物与服务端判定适配；先接已有一个电路任务。
4. B2：快照/关键事件、幂等与多标签冲突；教师查看单次实验。
5. C1：EDU16 语义、汇编解析和纯函数内核。
6. C2：程序/数据通路/寄存器 UI 与预测题。
7. C3：样板课堂整合、生产回归、文档。

每项都是可独立评审、可关闭入口的变更。实现期间不夹带平台导航整体改版或数据库技术栈替换。

## 13. 验收与发布策略

### 13.1 关键场景

| 领域 | 必须验证的场景 |
|---|---|
| 课程 | 草稿校验失败可定位；发布事务完整；复制新版本；旧实例固定旧行为 |
| 身份 | 跨班级读取/修改被拒绝；请求体伪造身份无效；小组共享范围正确 |
| 提交 | 丢响应重试、同键异内容、多标签冲突、暂停/结束时提交、新尝试独立 |
| CPU | 九条指令语义、溢出、JZ 两分支、非法编码、回绕、限额、浏览器/服务器一致 |
| 电路 | 等价拓扑、错误结果、位宽、递归子电路、unknown/error、生成题可解 |
| 3D | 正确/错误检查、拆装失效、工单隔离、GLB 失败、无 WebGL、刷新重检 |
| AI | 超时、取消、部分完成、非法动作、旧结果迟到、单步重生成不覆盖其他编辑 |
| 教师 | 从高频错误定位到产物；分页加载；复盘与现有里程碑关联 |

### 13.2 性能目标

保留项目已有课堂门禁：150 学生、最多 30 并发、API P95 ≤2000ms、零 SQLITE_BUSY。新事件接口需进入混合负载脚本并检查数据正确性；确认性能不足后再决定批量策略或数据库升级。

新增建议目标：CPU 在 1000 条指令限额内可及时暂停、界面无连续卡死；电路在前述规模预算下单次交互反馈目标 ≤100ms；超预算明确拒绝或引导缩小模型。测量注明机器、浏览器、样本和是否包含渲染。

3D 继续使用现有资产/构建预算，模型目标 ≤5MB、可见三角面 ≤100k；普通集显目标稳定达到 30 FPS 以上。该帧率是后续实测目标，不是本次保证。CPU、电路和3D按路由懒加载，避免教师首页加载全部模拟资源。

### 13.3 自动化入口

按受影响范围执行 `npm test` 和生产构建；课堂协议/写入变化执行 `npm run qa:classroom` 与 `npm run qa:classroom-load`；装机变化执行 `npm run qa:production`、`npm run qa:3d-budget` 及相应生产性能脚本；导航变化执行 `npm run qa:ui`。新增 CPU 场景纳入独立的生产浏览器回归，实施时添加入口。

浏览器检查沿用单个无头 Chromium、单 worker，只有双角色课堂场景使用所需的多上下文。此次文档修改只做内容、链接和差异检查，不重新运行全部应用测试。

### 13.4 迁移与回滚

新增表和可空关联字段优先采用增量迁移。先用现有数据副本验证旧课程、课堂、项目和成绩可读，再启用新入口；保留旧静态任务版本和导学适配器。

功能开关分别控制 CPU、电路升级、工单和 AI。关闭新入口不能隐藏已有学生提交；教师保留只读复核。回滚应用前确认旧版本能忽略新增字段，不通过删表恢复。正式迁移前备份并演练恢复；发布/推送在实际实施完成后按用户授权执行。

## 14. 风险、取舍与后续决策

| 风险 | 处理方式 |
|---|---|
| 通用课程引擎规模过大 | 先线性步骤、固定动作和一个样板课；新增能力由真实任务驱动 |
| 教学动画被误认为硬件事实 | 明确 EDU16 与微步骤语义；不报告未经建模的时间/性能指标 |
| 日志数量拖慢 SQLite | 保存关键操作、批量写入、有界记录，扩展混合负载验证 |
| 评分内核前后端漂移 | 共用纯函数、固定版本、服务端复算，私有评分配置隔离 |
| AI 生成无效课程 | schema/资源/参考解三层验证；教师预览后发布 |
| 模型精修影响交互和性能 | 保留锚点合同、拾取验证和预算；每次精修交付 GLB 与源文件 |
| 电路功能正确却因拓扑不同被误判 | 功能测试为主；结构要求必须显式写入题目 |
| 过程记录被当成独立完成证明 | 展示为操作证据；结合预测题、变体与人工解释评价 |

后续实施默认建议：先 A+B+C，采用 EDU16-ACC，保留当前数据库和视觉方向，正式通过以服务端判定为准。若教学大纲要求标准 RISC-V、希望先提升 3D 工单，或首期必须导入 OpenMAIC 文件，应在启动对应实现前调整阶段和验收范围。
