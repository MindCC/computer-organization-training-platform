# 装机练习服务端同步

用户已批准下一步优先实现服务端保存与恢复。本轮沿用 Express、SQLite 和现有学生登录，不扩展教师看板或正式成绩。

## 实现

1. 每个学生/订单保存一个版本化练习文档。身份来自会话，订单必须是有效教学订单；校验草稿与历史，恢复永远重新自检。
2. GET 获取文档和 revision；PUT 携带 baseRevision、operationId 和文档，事务比较版本并保存。相同操作重试不重复写入，旧版本返回 409 和服务器副本。
3. 浏览器保留本机文档和持久化待同步请求；串行同步、合并连续操作，断网/超时重试使用相同请求 ID。首次接入先读取服务器，避免空草稿覆盖已有进度。
4. 冲突时暂停上传，显示两份进度概况。学生选择恢复服务器进度或使用本机进度；两侧历史按会话去重合并。再次发生并发更新仍需重新解决冲突。
5. 显示读取、待同步、已同步、离线、登录失效、保存失败和冲突状态；切换身份/订单和组件卸载后停止网络工作。

## 验收

- API：未登录/角色/身份/订单隔离、无效文档、重复 ID、旧版本、多设备竞争、成绩不变。
- 同步控制器：断网重试、响应丢失、刷新待上传恢复、写入期间产生新操作、首次迁移、冲突双向选择、停止后不继续上传。
- 生产浏览器：已有三种练习回归；服务器跨浏览器恢复、断网恢复、冲突提示与选择；相关打包和资源预算。
