# 自定义客户与 AI 剧情

## 目标
新增独立于小林首日剧本的自由客户模式。玩家编辑名字、职业、性格，输入装机用途与元件预算，AI 分析后才产生剧情。使用原创立绘和现有店铺场景。

## 制作顺序
1. 原创客户立绘：米白外套、青绿上衣、眼镜与帆布包；名字、职业、性格由玩家定义，不预置经历。
2. 服务器调用现有 DeepSeek，返回需求解释、数值目标、待补信息、可选择的对话节点。严格校验 JSON、长度、目标和节点跳转；失败显示真实错误。
3. 玩家读对话、选择分支，比较真实目录计算的方案，然后进入现有 3D 装机、接线和开机自检。超出目录的需求显示缺口，不降低目标。
4. 服务端保存每个学生的生成订单，用保存的目标重新验收；自由订单不写入教材固定关卡成绩。恢复订单和装配进度时必须重新开机，不能恢复交付状态。
5. 验证需求缺失、AI 不可用、非法输出、订单归属、篡改目标、重复提交、预算不足、界面移动端、原剧本入口及真实 3D 回归。

## 边界
只向 AI 发送玩家主动输入的人物和装机需求及公开元件目录，不发送账户、成绩、凭证。AI 文本作为 React 文本展示，不能执行 HTML、跳过验机或修改既有关卡。

## 完成标准
可创建人物、生成真实 AI 订单和分支、选配、完成真实装机并收到服务器验收结果。API 超时或缺少配置时保留输入并允许重试；缺失信息时补充需求重新分析。

## API
- `GET /api/student/custom-customers/status`：当前 AI 配置是否可用（不返回密钥）。
- `POST /api/student/custom-customers`：人物名字/职业/性格、需求文本、整数元件预算；201 返回生成的订单、分析、目标、待补问题、对话节点。每人每分钟三次、最多一个进行中的生成。
- `GET /api/student/custom-customers/:id`：仅允许订单所属学生读取。
- `POST /api/student/custom-customers/:id/receipts`：提交元件选择与 operationId；服务器按存储的目标重新验收，同一标识重复提交返回相同回执，不同配置复用标识返回 409。
- 固定教学关卡的课程成绩不混入自由订单。AI 目标或材料不足时先补充需求，不能跳过需求校验。

## 检查
- `npm run qa:custom-customer` 在隔离数据库中执行生产 Edge 流程，显式调用真实 DeepSeek（需要既有 DEEPSEEK_API_KEY，会消耗模型额度）。其他浏览器检查继续屏蔽 AI 凭证。
- `scripts/probe-custom-ai.mjs` 是人工诊断脚本，只使用虚构人物和公开目录，响应落在忽略版本控制的 qa-artifacts，不输出凭证。
