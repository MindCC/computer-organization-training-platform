# 全平台流程与界面完善

## 目标

按学生、教师、访客的真实路径审核登录、课程首页、实验、装机店、题库与作业、错题本、知识库、课件和课堂管理。修复可复现的问题，改善状态反馈与界面一致性，保留现有课程内容、3D 操作、成绩和账户权限。最终提交到现有 main 并推送 gitee/main。

## 依据

- 既有浅色工坊风格、统一平台顶栏与分模块设计要求，见 prototype/AGENTS.md。
- PhET 直接操作、就近控制和即时反馈：https://phet.colorado.edu/publications/tech-award-2011-resources/PhET_TechAwards_Application.pdf
- NN/g 明确状态与下一步：https://www.nngroup.com/articles/visibility-system-status/
- 知识库侧栏参考 Obsidian；装机店经营变化见 prototype/docs/shop-variety-2026-10-04.md。

## 交付顺序

1. 建立现有功能基线：完整单元/API测试、学生及教师主要页面截图与导航检查。
2. 修复登录/同步/退出错误处理、真实状态与异常恢复；检查账户切换数据隔离。
3. 改进作业与课件的加载、失败、详情切换；完善知识库和错题本重试；将无实际内容的通知和帮助操作接入真实入口。
4. 审查桌面、缩放和手机布局，调整已发现的遮挡、溢出、字色与操作层级；保留已有模块风格。
5. 验收核心课程、装机交付、课件演示、学生作业、错题订正、知识上传及教师课堂流程。运行生产构建、资源与必要的课堂/3D门槛；记录未覆盖条件。
6. 审查 diff，排除本地日志、数据库、环境密钥和无关换行变更，提交并验证 gitee 推送回执。

## 已确认的审核风险

- 登录初始化把学情/笔记等业务加载失败当作未登录，可能让有效登录态掉回游客页。
- 顶栏通知数量固定为 3、帮助按钮仅改提示文字；需改成真实内容与可达路径。
- 教师作业吞掉加载错误，切换班级/作业时可能留下过时详情或异步拒绝。
- 课件分页笔记缺少过期请求保护，快速换页时可能显示上一页数据。
- 旧笔记 UI 的状态与 CRUD 仍留在 App 中但知识库不再使用；移除无效前端路径，不删除后台已有笔记数据。
- 后续装机客户仍存在文字工单呈现；本次优先确保已实现业务的清晰入口和一致性，新增诊断评分需明确任务模型后单独实现，不能以按钮占位冒充可玩内容。
