# 装机店新玩法：诊断与定向升级

## 目标
授权：用户要求“开始制作装机新玩法”。制作三个可玩维修工单：小周多任务内存不足、小许机械硬盘加载慢、阿澄处理器导出慢。保留全部原有装机任务。

## 完整流程
接待并阅读症状 → 三项基线检测 → 根据证据诊断 → 在真实 3D 预装主机中拆换必要元件 → 接线与开机 → 同项复测 → 服务端验收回执 → 下一工单。错误诊断可纠正，预算超支或性能未达标可继续调整。

## 实现
- 共享纯函数：目录、三种工作负载、模拟资源利用率/耗时、升级费用、证据检查与验收。数字来自模型，明确显示“教学模拟”，不声称实机性能。
- 独立服务端工单表：按账户恢复诊断进度，版本冲突保护，操作标识幂等；服务端计算测试与成绩，客户端不能提交任意指标或分数。限制每账户工单数量。
- 新界面按需加载，沿用暖色店铺、角色立绘、浅色工具台、青绿动作。检测按钮和结果同屏；手机自然重排，保留统一顶栏。
- 3D 工作台新增可选预装种子与证据回调。保留原来的拆装、插槽、双内存、接线、自检；刷新只恢复零件草稿，必须重新开机才能复测或交付。
- 学习记录加入独立维修记录，错题本接入诊断错误与重做入口。独立记录不覆盖原有装机和电路成绩。

## 验收
1. 行为测试覆盖三类瓶颈、不同升级效果、预算、容量、先测再诊断、结构证据和过期复测。
2. API 验证账户隔离、学生角色权限、操作重放/冲突、服务器评分、恢复与完成记录。
3. 单实例浏览器完成三个工单的真实 3D 更换、自检、复测和交付；验证错误诊断、刷新恢复、下一客户、学习记录/错题本与移动布局。
4. 原装机流程回归，完整测试与生产构建，保留 JS/3D 体积门槛。启动本地预览，提交并推送授权范围内更改。

## 风险和边界
教学模型说明单一瓶颈，不拟合具体品牌跑分。换硬盘表示客户资料已备份后更换，不模拟操作系统安装或真实文件复制。AI 不参与硬件判分；本轮不扩展经营财务、装饰、随机事件。
