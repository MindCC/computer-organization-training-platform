# 错题与演示页系统联动

## 目标

错题本覆盖实验、按章题库练习和教师课后作业；能够回到具体题目、查看解析并进行重练。平台内的独立演示页使用系统统一导航，随时返回课程、作业、错题本。

## 实施顺序

1. 将按章练习接入服务端账号记录，按课程题库真实判分；限制章节、题目、答案大小，使用提交标识保证重试不重复记账。保留账号隔离的本地草稿。
2. 错题本聚合实验失败、已作答的题库错题和已经判分的教师作业题。保留来源、原答、参考答案、解析和历史；未提交、未判分不作为错题。题库再次答对后标记已订正，重复答错恢复待复习。
3. 错题跳转到指定练习题或原教师作业；客观作业题在错题本独立重练，不修改原始作业成绩；简答题保留教师反馈与作业回看。
4. 用统一 App 外壳承载原始演示 HTML。开发和生产均将平台内独立演示链接导向外壳，内部框架加载原文件；复用品牌、主导航、用户菜单和明确返回入口。保留原教材算法、独立原始文件和同源成绩联动。
5. 验证账号隔离、未答/未批改处理、重试与订正、具体题目导航、所有演示页返回及真实练习记录；检查桌面/手机、构建及包体预算。

## 边界

- 保留现有实验错题及提交口径，作业重练独立于正式成绩。
- 演示文件作为 iframe 的原始教学内容，平台外独立文件继续可用；本任务只改变平台集成外壳，不修改教材演算法。
- 按章题库已有公开答案；教师作业答案仅在已判分的当前学生错题中返回。
- 保留课堂生命周期、3D 模型与已完成的首页/登录/学习树。
- 首屏 JavaScript 必须保持在现有 512000 B 预算内；新增页面按需加载。

## 完成标准

新错题由真实服务端提交产生，重新登录仍可见；点击能进入正确题目/作业，订正不改变原成绩。全部平台演示具有与实验室相同的顶栏，直接链接和返回都可用；原始演示交互、练习成绩及独立使用均正常。

## 实施结果

以上五项已完成。完整流程 13 项、演示真实判分与报告联动 9 项通过；详细实现、数据边界和验证记录见 `prototype/docs/learning-integration-2026-10-04.md`（仓库根目录路径）。
